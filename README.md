# cc-retain-lab

CC_Codex 二期（26.11）**数据工程**产品线：**留存裁撤台**（FastAPI + 原生 JS SPA + SQLite）。

## 一句话骨架（自有，非外仓抄题）

**分区留存策略版本 → 入库落库 → 到期扫描裁决 → 归档或销毁执行 → 策略与实物分区对账**

与现有六线正交（不是采集目录、ETL 管道、同步源、解析入库、编排流、种子摄取）。  
也不碰外仓常见指纹（Feed 归并 / 作业编排 / CDC 游标 / 质检签发 / 贴源-明细-汇总）。

## 领域

- **所属领域**：数据工程  
- **子方向**：数仓与数据湖（分区留存 / 裁撤闭环）

## 技术栈

| 层 | 选型 |
|----|------|
| 后端 | Python 3.12、FastAPI、Uvicorn、SQLite |
| 前端 | 原生 JS 单页（全中文），青灰底 + 铜强调，顶栏导航（非绿侧栏克隆） |
| 测试 | pytest + httpx（本地秒级闭环，优先于 compose） |

## 基线已通主链

1. 现行留存策略（主题域 / 保留天 / 到期动作）  
2. 实物分区列表（在线 / 归档 / 销毁）  
3. 按基准日到期扫描 → 生成待执行裁决  
4. 单条裁决执行（归档写地址 / 销毁清零）  
5. 策略与实物对账报告  

预留切口（未做，供后续功能题）：重裁作废、批量失败闭互斥、跨域依赖冻结、归档回灌等。

## 策略换版（整库原子切换）

全台只贯彻一条路径：**整库原子切换**。一次 `POST /api/policy-switch` 在一个事务
（`BEGIN IMMEDIATE`）内完成全库所有主题域的换版，不存在草稿态。

- **三处同改**：策略列表（现行 vN）、分区详情（分区版本 / 落库版本 / 同源标记）、
  扫描队列（策略快照版本）在同一事务内一起前进。
- **同源闸门**：事务提交前校验「每个域恰好 1 条现行版本 + 全部分区版本等于现行版」，
  偏一点即回滚，`switch_jobs` 记一条「失败」。
- **换版偏了即拦**：未完成裁决（待执行/执行中）随换版整体作废；旧版裁决再执行会被
  明确拒绝（409「裁决来自 vN，现行已是 vM」），不会与新版动作互殴。
- **扫描吃对版本**：扫描开头一次性锁定现行策略快照并落库到 `scan_jobs.policy_snapshot`，
  整轮只认这一份；分区版本与快照不同源则跳过并计数，绝不跨版本开单。
- **两人锁写**：换版与扫描都用 `BEGIN IMMEDIATE` 串行。并发时只有一人成功，另一人
  拿不到锁或 CAS 发现版本已被推走 → 409「被拦截」；`switch_jobs` 分别记「成功 / 被拦截」，
  不会双成功并盖掉对方。
- **锁竞争不冒 500**：换版、扫描、执行、落库、对账都在拿不到锁时统一回 409「被拦截」；
  `delete` 日志模式下 COMMIT 抢不到独占锁也归为此类，不会变成 500 或被误记成「失败」。
- **脏数据不拖垮扫描**：**先判版本、再判状态**；单条 `biz_date` 非法的分区会被跳过并计数，
  而不是让整轮扫描永久 500。落库入口对 `biz_date` / 行数 / 版本做严格校验，均返回 409。
- **不允许落库复活**：已归档/已销毁的分区不能被落库改回在线，避免「已销毁 + 非零行数」
  这种破坏分区层面同源的记录。

页面「策略换版」页可先看 preflight（现行版号、分区数、待作废裁决、同源状态），
提交后「换版任务」列表直接展示每次的基准版本→目标版本与成败。

## 入库落库

「入库落库」页把分区写入本机库，并盖上**落库当时的现行版本戳**
（`policy_version` / `landed_version`）。落库任务可复验：版本与现行不符直接 409。
换版后存量分区随全库重盖 `policy_version`，`landed_version` 保留写入时的版本以便追溯。
